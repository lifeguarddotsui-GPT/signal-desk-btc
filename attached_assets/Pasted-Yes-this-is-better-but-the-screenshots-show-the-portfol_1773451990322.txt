What is still wrong

The issue is no longer just “latency.” It is:

you are mixing fields from different freshness layers into one card.

For example:
	•	wallet balances may be verified already
	•	positions may still be loading from Typus / indexer / backend cache
	•	reward balances may come from another source
	•	pending sends / settlements may not yet be modeled at all

So the UI composes:
	•	verified wallet
	•	stale or missing position state
	•	missing rewards
	•	missing transfer ledger
	•	derived PnL from incomplete inputs

That creates false losses and psychological damage.

What to change now

You need to stop treating the portfolio card as a direct sum of ad hoc RPC results.

Instead, make it a backend-computed portfolio snapshot with explicit components:

Canonical portfolio formula

Total Economic Value = Wallets + Open Position Equity + In Transit + Claimable Rewards

And then:

Total PnL = Total Economic Value + Withdrawn Value - Net Deposited

Or if you do not track withdrawn yet:

Total PnL = Total Economic Value - Net Deposited

But only after all required components are valid.

The 4 required components

1. Wallets

Verified SUI/free collateral currently present in agent wallets or user wallet depending on scope.

2. Open Position Equity

Not just “position exists.”
This should include:
	•	current margin/collateral tied to position
	•	unrealized PnL
	•	fees if known
	•	pending close state if closing has been requested but not finalized

3. In Transit

This is currently missing in practice.

This bucket should include all value that has left one place but has not yet been verified in the destination.

Examples:
	•	agent sending funds back to user wallet
	•	settlement requested from Typus but not reflected yet
	•	close order executed but collateral not recredited yet
	•	rewards being moved but not arrived
	•	internal wallet rebalance pending confirmation

This needs its own ledger and UI section.

4. Claimable Rewards

This should mirror the “claimable now” balance exactly, or be a backend-synced version of it.
Do not leave it at 0.00 if claimable rewards exist elsewhere in the product.

Why positions still feel slow

Because open positions are the hardest part:
	•	exchange state
	•	mark price
	•	close/fill status
	•	settlement status
	•	wallet credit timing

You need to track positions by lifecycle, not just “is there an open position right now.”

Position lifecycle model

Every position should move through these states:

PENDING_OPEN
OPEN
REDUCING
PENDING_CLOSE
CLOSED_UNSETTLED
SETTLING
SETTLED
FAILED

And the frontend should keep the position visible through the whole lifecycle.

Important rule

Do not remove a position from the portfolio the instant the exchange says it is closed.

Instead:
	•	move it from Open Positions
	•	into In Transit / Settling
	•	keep its last known notional / realized outcome attached
	•	only remove it when wallet credit is verified

That is the main reason users currently feel money “vanished.”
