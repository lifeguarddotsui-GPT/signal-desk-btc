Updated fix recommendations

1. Redefine “successful close”

Your code should treat a close as successful only if at least one of these is true:

type VerifiedCloseResult = {
  txSuccess: boolean;
  positionObjectDeleted: boolean;
  settlementAmountMist: bigint;
  balanceIncreaseMist: bigint;
  protocolStateClosed: boolean;
};

And the check:

function isVerifiedClose(r: VerifiedCloseResult): boolean {
  return (
    r.txSuccess &&
    (
      r.positionObjectDeleted ||
      r.settlementAmountMist > 1_000_000n || // example threshold, tune as needed
      r.balanceIncreaseMist > 1_000_000n ||
      r.protocolStateClosed
    )
  );
}

Do not count dust like 414240 mist as a real close.

⸻

2. Add a dust-threshold rule

Any txn with only a tiny change like this should be classified as:
	•	NON_SETTLING_SUCCESS
or
	•	DUST_ONLY_TX

Example:

const DUST_THRESHOLD_MIST = 1_000_000n; // 0.001 SUI, adjust as needed

if (txSuccess && balanceIncreaseMist > 0n && balanceIncreaseMist < DUST_THRESHOLD_MIST) {
  status = "DUST_ONLY_TX";
}

This will stop the app from confusing noise with real settlement.

⸻

3. After every close attempt, inspect object changes

You need post-tx inspection that explicitly looks for:
	•	deleted position object
	•	mutated/removed receipt object
	•	created/returned collateral coin
	•	events indicating close/settle

If only a generic SUI coin changed, that is not enough.

⸻

4. Force a reconcile-before-close

Before close:
	•	fetch all owned protocol objects
	•	identify live position object
	•	identify any receipt object
	•	identify linked order objects
	•	identify stale/orphaned order objects

Then decide which exact object is used in the close path.

⸻

5. Cancel-linked-orders must not be mistaken for settlement

Keep this strict separation:
	•	cancelBlockingOrders()
	•	refreshPositionArtifacts()
	•	closePosition()
	•	verifySettlement()

Not one blended method.
