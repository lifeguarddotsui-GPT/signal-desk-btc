Problem diagnosis

The current “close” flow is not actually completing the full lifecycle of a position close.

From the screenshots:
	•	the wallet shows many Contract Interaction and cancel_trading_order calls
	•	the funding wallet is not receiving inflows
	•	UI still shows In Transit 5.00 and Closing pos. 5.00
	•	this means the system is likely doing order cancellation only, not full position exit + settlement + return-to-funding-wallet

Core conclusion

cancel_trading_order is not the same thing as closing a live position.

Your agent is probably stuck in one of these failure states:
	1.	It cancels resting TP/SL or exit orders, but never sends the actual reduce-only market close.
	2.	It sends the close, but never confirms the position size reached zero onchain.
	3.	It closes the position, but never runs the post-close settlement/withdraw/claim step.
	4.	It settles to the wrong wallet/object path instead of the agent funding wallet.
	5.	The backend marks funds as “in transit” before final settlement, but never clears that state when inflow is missing.

Instructions for Replit agent

1) Split the close pipeline into explicit stages

Replace the current vague “close position” logic with a strict state machine:

type PositionCloseState =
  | "IDLE"
  | "CANCEL_EXIT_ORDERS"
  | "SUBMIT_REDUCE_ONLY_CLOSE"
  | "WAIT_POSITION_ZERO"
  | "SETTLE_CLAIM_FUNDS"
  | "WAIT_WALLET_INFLOW"
  | "DONE"
  | "FAILED";

Each stage must complete before the next begins.

2) Never treat order cancellation as a successful close

Current bug appears to be:
	•	cancel exits
	•	assume close happened
	•	mark capital as in transit
	•	never verify inflow

Add this rule:

// DO NOT mark a position closed just because orders were cancelled.
if (action === "cancel_trading_order") {
  // This only removes pending orders.
  // It does not reduce position size.
  position.closeProgress.ordersCancelled = true;
  position.closeProgress.positionClosed = false;
}

Success criteria for closure must be:

position.size === 0

Not:
	•	tx success
	•	cancel success
	•	no open orders
	•	UI assumption

3) Close the actual position with a reduce-only exit

After cancelling stale TP/SL orders, submit a true closing order against the live position.

Required rules:
	•	opposite side of current position
	•	reduce-only
	•	preferred order type: market or aggressive IOC
	•	quantity = exact live position size from chain
	•	do not reuse stale cached size

Example:

const livePos = await getLivePosition(positionId);

if (!livePos || livePos.size <= 0) {
  throw new Error("No live position size found for close");
}

await submitCloseOrder({
  market: livePos.market,
  side: livePos.side === "LONG" ? "SELL" : "BUY",
  size: livePos.size,
  reduceOnly: true,
  orderType: "MARKET", // or IOC aggressive limit
});

5) Add mandatory post-close settlement step

This is likely the missing piece.

Once size hits zero, run the exchange/protocol-specific settlement/claim/withdraw flow.

Pseudo-flow:

if (positionIsZero(positionId)) {
  await settleClosedPosition(positionId);
}

That function must:
	•	identify the closed position object / account object
	•	call the correct settlement endpoint / move call
	•	receive proceeds back to the agent funding wallet
	•	log all returned coin object IDs and balances

Example structure:

async function settleClosedPosition(positionId: string) {
  const settlementTarget = await getSettlementTarget(positionId);

  if (!settlementTarget) {
    throw new Error(`Missing settlement target for ${positionId}`);
  }

  const tx = await executeSettlement({
    positionId,
    settlementTarget,
    recipient: agent.fundingWalletAddress,
  });

  return tx;
}

async function reconcileUnsettledClosures() {

    where: { closeState: "SETTLE_CLAIM_FUNDS" }

  for (const pos of pending) {
    const livePos = await getLivePosition(pos.positionId);

    if (!livePos || livePos.size === 0) {
      const inflowFound = await detectRecentFundingWalletInflow(pos.fundingWallet, pos.closedAt);

    }
  }
}
