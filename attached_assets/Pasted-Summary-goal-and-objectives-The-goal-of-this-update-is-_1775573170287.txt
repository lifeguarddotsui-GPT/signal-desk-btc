Summary: goal and objectives

The goal of this update is to make probability scoring visible, persistent, and trainable across the full Blue Water trading lifecycle.

Objectives
	1.	Show a clear probability score on every open and closed position.
	2.	Make each trade outcome act as a live calibration signal:
	•	win = probability was supported
	•	loss = probability was overstated or miscalibrated
	3.	Improve UI so users can quickly understand:
	•	how confident the agent was
	•	whether that confidence was justified
	•	how accurate the system has been over time
	4.	Strengthen the live-learning loop so the probability engine becomes more reliable from real trades only.

This does not mean every 80 score must win or every 30 score must lose. It means that over time, a probability bucket should behave roughly as expected. For example:
	•	trades scored 70–79 should win materially more often than trades scored 50–59
	•	trades scored 85+ should be rare and high quality
	•	if 80-score trades are not outperforming, the model is miscalibrated and must be corrected

That is the right way to build a real probability-confidence system.

Useful suggestions before implementation

1. Show both formats: internal 0.01–0.99, UI 1–99

Use:

	•	display value: integer 1–99

Example:
	•	internal 0.74
	•	UI shows 74

This keeps the model mathematically clean while making the interface easy to read.

⸻

2. Freeze the probability at entry

Once a trade opens, the entry probability must be locked and stored with that position.

Do not keep changing the displayed probability after entry, or the training signal becomes meaningless.

You may optionally show:
	•	Entry Probability = frozen
	•	Current Live Probability = optional recalculated live score

But the training system must always grade the entry probability.

⸻

3. Grade calibration by buckets, not by single trade

Do not judge the model from one trade. Judge it by groups:
	•	50–59
	•	60–69
	•	70–79
	•	80–89
	•	90–99

For each bucket track:
	•	trade count
	•	actual win rate
	•	average pnl
	•	calibration gap

Example:
	•	bucket 70–79
	•	expected win rate ~ 75%
	•	actual win rate 58%
	•	model is overstating confidence in that band

This is far more useful than “this one 82 lost.”

⸻

4. Add a calibration penalty

If a bucket is consistently overstated, probability output should be reduced automatically.

Example:
	•	if 80–89 bucket is underperforming badly over the last 25+ trades
	•	apply a confidence haircut to future trades in that band

This will make the probability engine self-correct faster.

6. Separate probability from confidence

Keep both fields internally:

UI can emphasize probability, but confidence should still exist in diagnostics.
A 74 probability with low confidence is very different from a 74 with high confidence.

2.2 Add probability bucket resolver

Create file: server/probability-buckets.ts

export interface ProbabilityBucket {
  label: string;
  minDisplay: number;
  maxDisplay: number;
  midpointProbability: number;
}

export function resolveProbabilityBucket(displayScore: number): ProbabilityBucket {
  if (displayScore >= 90) return { label: "90-99", minDisplay: 90, maxDisplay: 99, midpointProbability: 0.945 };
  if (displayScore >= 80) return { label: "80-89", minDisplay: 80, maxDisplay: 89, midpointProbability: 0.845 };
  if (displayScore >= 70) return { label: "70-79", minDisplay: 70, maxDisplay: 79, midpointProbability: 0.745 };
  if (displayScore >= 60) return { label: "60-69", minDisplay: 60, maxDisplay: 69, midpointProbability: 0.645 };
  if (displayScore >= 50) return { label: "50-59", minDisplay: 50, maxDisplay: 59, midpointProbability: 0.545 };
  return { label: "01-49", minDisplay: 1, maxDisplay: 49, midpointProbability: 0.25 };
}

Rule

Every trade must be assigned a probability bucket at entry.

3.3 Add calibration interpretation

Create helper:

export function resolveCalibrationStatus(calibrationGap: number): "OVERSTATED" | "CALIBRATED" | "UNDERSTATED" {
  if (calibrationGap <= -0.08) return "OVERSTATED";
  if (calibrationGap >= 0.08) return "UNDERSTATED";
  return "CALIBRATED";
}

Meaning:
	•	OVERSTATED = model is too optimistic
	•	UNDERSTATED = model is too conservative
	•	CALIBRATED = roughly behaving correctly

4.2 Add calibration penalty to scoring

Update server/win-probability-model.ts

After raw probability is computed, but before final approval, apply a calibration adjustment using recent bucket performance.

Example rule
	•	if recent 80-89 bucket actual win rate is much lower than expected
	•	reduce high-end probability outputs by a haircut

Pseudo logic:

if (predictedDisplayScore >= 80 && bucketCalibrationGap < -0.08) {
  probability -= 0.03;
}
if (predictedDisplayScore >= 90 && bucketCalibrationGap < -0.10) {
  probability -= 0.05;
}

Goal

Stop the system from repeatedly overstating elite setups.
