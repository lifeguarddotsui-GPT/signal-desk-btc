You have a state-management and position-lifecycle problem, not just a UI problem.

From the screenshots, the same portfolio flips between roughly these states within minutes:
	•	positions shows Loading while also saying 2 open · live
	•	positions later shows Loading with 6 open · live
	•	positions later resolves to 60.00
	•	total economic value jumps from 99.54 to 89.76 to 29.76
	•	total PnL jumps from about -0.46 to -10.24 to -70.24
	•	reconciliation swings from 53% reconciled to 100% reconciled
	•	drift changes materially while positions are still unresolved

That means the frontend is recomputing portfolio totals from incomplete snapshots and is not retaining the last known good open-position set while live refreshes are in flight.

Core diagnosis

The frontend is likely doing one or more of these:
	1.	Replacing the entire open-position array with each fresh poll result, even when that result is partial or temporarily empty.
	2.	Treating “RPC returned no positions yet” as “no positions exist”.
	3.	Computing portfolio value before position hydration completes.
	4.	Not preserving position identity across refreshes.
	5.	Not modeling order lifecycle separately from position lifecycle.
	6.	Losing track of positions during:
	•	order submitted but not yet filled
	•	partial fill
	•	close submitted but not yet settled
	•	keeper settlement / exchange lag
	•	websocket disconnect / refresh / tab reload

Correct logic

Open positions must be treated as durable tracked entities with lifecycle state, not as a transient number from the latest API response.

The frontend should never derive “current open positions” from a single source or a single poll tick.

Instead, build a Position Recovery + Retention pipeline:

Position truth priority

Use this order of trust:
	1.	Local tracked position registry
Last known good position set keyed by stable position ID
	2.	Backend canonical reconciler
	3.	Exchange/venue live position endpoint
	4.	Recent order/fill events
	5.	Wallet/collateral deltas as fallback inference

If source 3 temporarily returns empty, do not wipe source 1.

3) Add a stable position identity strategy

A major bug is often that every refresh creates a “new” position object because the app lacks a stable ID.

Preferred stable ID

Use venue-native position ID if available.

Fallback synthetic fingerprint

If no stable venue ID exists, compute one:

function makePositionFingerprint(input: {
  agentId: string;
  venue: string;
  symbol: string;
  side: "long" | "short";
  entryBucket: string; // rounded entry price bucket
  openedAtBucket: string; // rounded timestamp bucket
}) {
  return `${input.agentId}:${input.venue}:${input.symbol}:${input.side}:${input.entryBucket}:${input.openedAtBucket}`;
}

Round price/time enough to survive tiny discrepancies.

4) Build a merge-based reconciler, never replace-based

Current bug likely:

state.positions = api.positions;

That is wrong.

Do this instead:

function mergePositions(
  existing: Map<string, PositionRecord>,
  incoming: PositionRecord[],
  now: number
): Map<string, PositionRecord> {
  const next = new Map(existing);

  for (const pos of incoming) {
    const prev = next.get(pos.id);

    if (!prev) {
      next.set(pos.id, {
        ...pos,
        firstSeenAt: now,
        lastSeenAt: now,
        lastVerifiedAt: now,
        lifecycle: pos.lifecycle ?? "open_verified",
        sourceConfidence: "high",
        version: 1,
      });
      continue;
    }

    next.set(pos.id, {
      ...prev,
      ...pos,
      lastSeenAt: now,
      lastVerifiedAt: now,
      lifecycle: upgradeLifecycle(prev.lifecycle, pos.lifecycle),
      sourceConfidence: strongerConfidence(prev.sourceConfidence, pos.sourceConfidence),
      version: prev.version + 1,
    });
  }

  return next;
}

Do not erase unseen positions immediately.

5) Use disappearance TTL before removing positions

If a position vanishes from one source, move it into recovery, not deletion.

const POSITION_MISSING_TTL_MS = 45_000;
const POSITION_ORPHAN_TTL_MS = 180_000;

Logic
	•	Missing for < 45s: keep displayed as open, mark stale
	•	Missing for 45–180s: mark orphaned_recovering
	•	Only remove after explicit closure proof or long TTL expiry plus supporting evidence

Closure proof means one of:
	•	exchange reports closed
	•	close fill detected
	•	realized pnl event tied to that position
	•	collateral returned / settlement confirmed
	•	backend reconciler marks closed

function getDisplayPositionValue(state: PositionsState): {

    label: "awaiting first sync",
    confidence: "low",
  };
}

	1.	fetch backend snapshot
	2.	merge incoming positions into registry

Example reducer skeleton

function reconcilePositionRegistry(params: {
  registry: Map<string, PositionRecord>;
  incomingVerified: PositionRecord[];
  incomingRecovering: PositionRecord[];
  now: number;
}) {
  let registry = new Map(params.registry);

  registry = mergePositions(registry, params.incomingVerified, params.now);
  registry = mergePositions(registry, params.incomingRecovering, params.now);

  for (const [id, pos] of registry.entries()) {
    const unseenMs = params.now - pos.lastSeenAt;

    if (
      (pos.lifecycle === "open_verified" || pos.lifecycle === "open_unverified") &&
      unseenMs > 45_000
    ) {
      registry.set(id, {
        ...pos,
        lifecycle: "orphaned_recovering",
        sourceConfidence: "low",
      });
    }

    if (pos.lifecycle === "closed_verified" && unseenMs > 180_000) {
      registry.delete(id);
    }
  }

  return registry;
}

Example display selector

function selectPositionsCard(registry: Map<string, PositionRecord>) {
  const active = [...registry.values()].filter((p) =>
    ["opening_pending", "open_unverified", "open_verified", "reducing", "closing_pending", "orphaned_recovering"]
      .includes(p.lifecycle)
  );

  const verified = active.filter((p) => p.lifecycle === "open_verified");
  const recovering = active.filter((p) => p.lifecycle === "orphaned_recovering");

  const verifiedValue = verified.reduce((sum, p) => sum + (p.notionalUsd ?? 0), 0);
  const recoveringValue = recovering.reduce((sum, p) => sum + (p.notionalUsd ?? 0), 0);

  return {
    count: active.length,
    verifiedCount: verified.length,
    recoveringCount: recovering.length,
    displayValue: verifiedValue + recoveringValue,
    status:
      recovering.length > 0
        ? `${verified.length} verified + ${recovering.length} recovering`
        : "verified",
  };
}
