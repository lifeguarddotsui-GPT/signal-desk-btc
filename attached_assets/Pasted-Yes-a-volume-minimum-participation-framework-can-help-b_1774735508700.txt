B. Liquidity Trap Hunting

Objective

Exploit stop-hunts and fake breakouts around local support and resistance instead of getting trapped by them.

Concept

These setups happen when:
	•	price briefly breaks a local high or low
	•	breakout traders enter
	•	stops are swept
	•	price fails to continue
	•	market snaps back inside the range

That reversal is the opportunity.

Where to run it
	•	Structure: 15m
	•	Trigger: 5m
	•	Optional fine trigger: 1m confirmation only if execution quality is good

Trap types

1. Upside liquidity trap
	•	price wicks above local resistance
	•	closes back below resistance
	•	volume spikes but follow-through is weak
	•	short entry

2. Downside liquidity trap
	•	price wicks below local support
	•	closes back above support
	•	sell pressure fails
	•	long entry

Detection logic

type LiquidityTrapSignal = {
  detected: boolean;
  side: "LONG" | "SHORT" | null;
  trapStrength: number; // 0-100
};

Build local structure

Use the last 24–48 candles on 5m/15m:

rangeHigh = highest recent swing cluster
rangeLow = lowest recent swing cluster

Trap conditions

Short trap fade

if (
  candle.high > rangeHigh &&
  candle.close < rangeHigh &&
  wickAboveBodyRatio >= 1.5 &&
  followThroughFailed &&
  volumeSpikeRelative >= 1.1
) => short trap

Long trap fade

if (
  candle.low < rangeLow &&
  candle.close > rangeLow &&
  wickBelowBodyRatio >= 1.5 &&
  followThroughFailed &&
  volumeSpikeRelative >= 1.1
) => long trap

Confirmation

Require at least one:
	•	next 5m candle confirms reversal direction
	•	RSI snaps back from extreme
	•	MACD histogram improves in reversal direction
	•	reclaim of EMA7 on 5m

Trap strength scoring

score = 0
+25 wick sweep beyond key level
+20 close back inside range
+15 failed follow-through next candle
+15 RSI reversal from stretched zone
+15 volume spike without continuation
+10 reclaim/loss of EMA7 in reversal direction

Entry rules

score >= 60 => valid trap entry
score >= 75 => strong trap entry, allow 1.2x base size

Risk rules

Liquidity traps are fast trades:

tpBps = 35 to 80
slBps = 20 to 35
maxHoldMinutes = 5 to 18

Kill switch

Do not fade if breakout is real:

if two consecutive closes hold outside range:
   invalidate trap

Replit implementation brief

function detectLiquidityTrap(ctx): LiquidityTrapSignal {
  let score = 0;
  let side: "LONG" | "SHORT" | null = null;

  if (
    ctx.candle.high > ctx.rangeHigh &&
    ctx.candle.close < ctx.rangeHigh
  ) {
    score += 25;
    side = "SHORT";
    if (ctx.upperWickRatio >= 1.5) score += 20;
    if (ctx.failedFollowThrough) score += 15;
    if (ctx.rsiReversal) score += 15;
    if (ctx.volumeSpikeNoContinuation) score += 15;
    if (ctx.emaFlipConfirmed) score += 10;
  }

  if (
    ctx.candle.low < ctx.rangeLow &&
    ctx.candle.close > ctx.rangeLow
  ) {
    score += 25;
    side = "LONG";
    if (ctx.lowerWickRatio >= 1.5) score += 20;
    if (ctx.failedFollowThrough) score += 15;
    if (ctx.rsiReversal) score += 15;
    if (ctx.volumeSpikeNoContinuation) score += 15;
    if (ctx.emaFlipConfirmed) score += 10;
  }

  return {
    detected: score >= 60,
    side,
    trapStrength: score,
  };
}

C. Dynamic Threshold System

Objective

Stop using the same signal strictness in all environments.

A rigid score threshold causes:
	•	too many idle periods in chop
	•	too many missed small opportunities
	•	bad fit across regimes

The threshold should adapt to:
	•	volatility
	•	volume
	•	regime
	•	recent agent performance
	•	capital utilization

Core idea

Instead of:

enterTrade if score >= 70

Use:

enterTrade if score >= dynamicThreshold

Inputs to dynamic threshold

dynamicThreshold depends on:
- market regime
- tradability score
- current volatility
- current relative volume
- recent win/loss streak
- capital utilization today

Example baseline thresholds

TREND mode:        65
CHOP_SCALP mode:   50
MICRO_SCALP mode:  45
BREAKOUT mode:     70

Adjustment rules

Lower threshold when:
	•	tradability is good
	•	volatility is low but not dead
	•	capital utilization too low
	•	no trades for long time
	•	recent setups have been missed

Raise threshold when:
	•	recent losses cluster
	•	volume is poor
	•	spread worsens
	•	breakout conditions become unstable
	•	slippage spikes

Example formula

threshold = baseThreshold

if tradabilityScore >= 75: threshold -= 5
if capitalUtilizationTodayPct < 20: threshold -= 3
if minutesSinceLastTrade > 90: threshold -= 2

if recentLosses >= 2: threshold += 4
if spreadBps > maxSpreadBps * 0.85: threshold += 3
if relative1hVolume < 0.6: threshold += 4

Clamp:

threshold = clamp(threshold, 42, 75)

Important safeguard

Never lower threshold below a hard floor.

That floor prevents pure random trades.

Replit implementation brief

function computeDynamicThreshold(ctx) {
  let threshold = ctx.baseThreshold;

  if (ctx.tradabilityScore >= 75) threshold -= 5;
  if (ctx.capitalUtilizationTodayPct < 20) threshold -= 3;
  if (ctx.minutesSinceLastTrade > 90) threshold -= 2;

  if (ctx.recentLosses >= 2) threshold += 4;
  if (ctx.spreadBps > ctx.maxSpreadBps * 0.85) threshold += 3;
  if (ctx.relative1hVolume < 0.6) threshold += 4;
  if (ctx.oracleFreshnessBad) threshold += 10;

  return Math.max(42, Math.min(75, threshold));
}

D. Micro Scalping (Anti-Idle Core)

Objective

Harvest small, frequent moves during otherwise boring conditions so capital is not stuck doing nothing.

Role

This should be the anti-idle fallback module, not the main system all the time.

Use it when:
	•	market is tradable
	•	chop or ultra-low-volatility regime exists
	•	normal setups are sparse
	•	spreads and fills are still acceptable

Timeframes
	•	regime: 15m or 1h
	•	micro setup: 3m or 5m
	•	optional execution refinement: 1m if stable

Do not make the whole engine 1m-only unless fills are very reliable.

What it trades
	•	small bursts away from mini support/resistance
	•	short-lived momentum pulses
	•	quick mean reversion reactions
	•	reclaim/loss of short EMA after compression

Valid micro setups

1. Micro support bounce long
	•	price tags local 3m/5m support
	•	RSI is stretched short-term
	•	small reversal candle appears
	•	enter long for quick scalp

2. Micro resistance rejection short
	•	price tags local resistance
	•	upper wick or stall candle
	•	momentum slows
	•	enter short

3. Compression release scalp
	•	candles compress tightly
	•	range narrows
	•	short expansion candle appears
	•	enter in direction of release for very short hold

Micro scalping parameters

tpBps = 10 to 25
slBps = 8 to 15
leverage = 12x to 22x
maxHoldMinutes = 3 to 10

This module is about speed and discipline, not hero trades.

Filters

Only allow if:

tradabilityScore >= 60
relative1hVolume >= 0.65
spreadBps <= acceptableMicroSpread
no major breakout event in progress

Micro score model

score = 0
+20 price at local micro support/resistance
+15 short-term RSI stretched
+15 rejection or reversal candle
+15 micro EMA reclaim/loss
+15 short burst in volume
+10 alignment with 15m structure
+10 compression release or micro trap

Fire threshold

score >= 45 => valid micro scalp
score >= 55 => strong micro scalp

Anti-overtrading controls

Micro scalping can become dangerous fast.

Add:
	•	max 2 consecutive micro losses before cooldown
	•	max 4 micro trades per hour per agent
	•	if two stop-outs occur in 20 minutes, disable micro mode for 45 minutes

function scoreMicroScalp(ctx) {

  return score;
}
