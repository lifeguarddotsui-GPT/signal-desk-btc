3) Fix flow

Here is the direct fix.

Root problem

Your agent is likely confusing at least one of these:
	•	DB position UUID
	•	frontend synthetic position id
	•	market/order id
	•	linked order object id
	•	actual on-chain position object id
	•	actual settlement/receipt object id

And the close flow is probably using the wrong one.

⸻

Correct close architecture

A. Never close from DB UUID

Do not let closePosition() accept a database UUID as if it were the on-chain object.

You need a strict distinction:

type DbPositionId = string;        // internal UUID
type ChainObjectId = `0x${string}`; // actual Sui object ID

Guard it hard:

function assertChainObjectId(id: string): asserts id is `0x${string}` {
  if (!id.startsWith("0x")) {
    throw new Error(`Expected on-chain object id, got: ${id}`);
  }
}


⸻

B. Persist all on-chain artifacts at entry time

When a position is opened, store all of these immediately from the txn response:

type OpenPositionArtifacts = {
  marketId: string;
  positionObjectId?: `0x${string}`;
  receiptObjectId?: `0x${string}`;
  orderObjectId?: `0x${string}`;
  linkedOrderObjectIds: `0x${string}`[];
  collateralCoinObjectIds: `0x${string}`[];
  txDigest: string;
};

If you do not persist these at open time, your close flow becomes guesswork.

⸻

C. Build a reconciliation layer

Before closing, reconcile from chain.

For every open DB position:
	1.	fetch wallet-owned objects
	2.	map known objects by type
	3.	identify:
	•	live position object
	•	receipt object
	•	linked order objects
	•	claimable/settlement object if protocol uses one

Pseudo-logic:

async function reconcilePositionArtifacts(agentAddress: string, dbPos: DbPosition) {
  const owned = await suiClient.getOwnedObjects({
    owner: agentAddress,
    options: {
      showType: true,
      showContent: true,
      showOwner: true,
    },
  });

  // Match by known package/module/type patterns from the protocol
  const positionObj = owned.data.find(o => isTypusPositionObject(o));
  const receiptObj = owned.data.find(o => isTypusReceiptObject(o));
  const linkedOrders = owned.data.filter(o => isTypusLinkedOrderObject(o));

  return {
    positionObjectId: positionObj?.data?.objectId,
    receiptObjectId: receiptObj?.data?.objectId,
    linkedOrderObjectIds: linkedOrders.map(o => o.data!.objectId as `0x${string}`),
  };
}

D. Close flow must be sequenced

Your close flow should be:

Step 1: Reconcile actual chain objects

Get the true on-chain position artifacts.

Step 2: Cancel linked orders only if required

Only cancel linked orders that block settlement.

Step 3: Refresh state after cancellation

Do not assume the original object references are still valid.

Step 4: Execute the real close call

Pass the actual required position/receipt object(s).

Step 5: Confirm settlement effects

After tx success, verify:
	•	SUI balance increased, or
	•	collateral object returned, or
	•	position object deleted/closed, or
	•	protocol marked position closed

Step 6: Only then mark DB position closed

⸻

Critical implementation rule

A transaction is not a close just because it succeeded.

A transaction only counts as a close if at least one of these is true:

type CloseVerification = {
  positionObjectGone: boolean;
  settlementReturned: boolean;
  walletBalanceIncreased: boolean;
  protocolReportsClosed: boolean;
};

Require something like:

function isRealClose(v: CloseVerification) {
  return (
    v.positionObjectGone ||
    v.settlementReturned ||
    v.walletBalanceIncreased ||
    v.protocolReportsClosed
  );
}

If none are true, log it as:

status = "NON_SETTLING_SUCCESS";

Not closed.
