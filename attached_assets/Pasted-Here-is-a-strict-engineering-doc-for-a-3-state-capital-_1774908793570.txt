Here is a strict engineering doc for a 3-state capital recovery and growth system.

Blue Water Agents — Capital State Machine

Modes: Accelerate, Recuperate, Restart

Objective

Create a portfolio-state controller above the normal signal/risk engine that changes behavior based on recent equity performance.

This controller must classify every agent into one of three capital states:
	•	Accelerate — press advantage, grow faster, allow larger trades
	•	Recuperate — recover losses with tighter controls and high-quality participation
	•	Restart — stop trying to save a damaged agent, withdraw, archive, and rotate to a fresh agent

This system must be visible in UI, logged in DB, and enforced in sizing, leverage, signal selection, and execution behavior.

⸻

1. Core Concept

Each agent has:
	•	starting equity baseline
	•	rolling equity peak
	•	current equity
	•	drawdown %
	•	recovery gap %
	•	recent pnl velocity
	•	recent win/loss cluster state

These values feed a Mode Controller which chooses:
	•	ACCELERATE
	•	RECUPERATE
	•	RESTART

The selected mode then modifies:
	•	risk per trade
	•	leverage behavior
	•	signal entry requirements
	•	max open positions
	•	cooldowns
	•	exit aggression
	•	whether the agent may continue trading at all

⸻

2. Mode Definitions

A. Accelerate

Purpose

Increase growth rate when the agent is healthy and trading well.

Intent
	•	larger position sizes
	•	more aggressive leverage usage
	•	more participation
	•	trend continuation allowed
	•	quicker re-entry after good trades

Conditions

Use Accelerate only when:
	•	current equity is near or above recent peak
	•	drawdown is low
	•	recent pnl is positive
	•	execution quality is acceptable
	•	win quality is strong, not just raw win rate

Color
	•	Emerald / Bright Green
	•	Suggested token: #16C784

UI label
	•	ACCELERATE
	•	subtitle: Growth mode

⸻

B. Recuperate

Purpose

Recover moderate losses without blowing up the remaining capital.

Intent
	•	continue trading
	•	reduce size
	•	prioritize high-quality setups
	•	improve precision
	•	avoid revenge trading
	•	recover methodically

Conditions

Use Recuperate when:
	•	equity is below peak by moderate amount
	•	loss cluster exists
	•	recent pnl is negative
	•	capital is still salvageable

Color
	•	Amber / Gold
	•	Suggested token: #F5B942

UI label
	•	RECUPERATE
	•	subtitle: Recovery mode

⸻

C. Restart

Purpose

Stop trading a damaged agent once capital impairment is too severe.

Intent
	•	disable new entries
	•	close residual exposure
	•	archive or mark agent unhealthy
	•	optionally transfer remaining capital
	•	recommend or automate redeployment of a fresh agent

Conditions

Use Restart when:
	•	drawdown breaches hard threshold
	•	equity too low to trade efficiently
	•	repeated losses persist despite Recuperate mode
	•	execution quality or close behavior has degraded badly
	•	remaining capital is better used in a new deployment than continuing this one

Color
	•	Red / Crimson
	•	Suggested token: #E5484D

UI label
	•	RESTART
	•	subtitle: Capital preservation

4. Mode Threshold Rules

These should be configurable globally, with optional per-agent override.

Config

type CapitalModeConfig = {
  accelerateMaxDrawdownPct: number;   // default 0.025
  accelerateMinRecentPnL: number;     // default > 0
  accelerateMinExecQuality: number;   // default 65
  accelerateMinSignalQuality: number; // default 65

  recuperateMaxDrawdownPct: number;   // default 0.12
  recuperateMinEquityPctOfStart: number; // default 0.70

  restartDrawdownPct: number;         // default 0.12
  restartMinEquityPctOfStart: number; // default 0.65
  restartLossStreak: number;          // default 5
  restartMaxSlippageBps: number;      // default 35

  hysteresisBufferPct: number;        // default 0.01
  minModeDurationMin: number;         // default 30
};

Default logic

function determineCapitalMode(
  ctx: CapitalModeContext,
  cfg: CapitalModeConfig
): CapitalMode {
  const equityPctOfStart = ctx.currentEquity / ctx.startingEquity;

  // Hard failure first
  if (
    ctx.drawdownPct >= cfg.restartDrawdownPct ||
    equityPctOfStart <= cfg.restartMinEquityPctOfStart ||
    ctx.recentLossStreak >= cfg.restartLossStreak ||
    ctx.avgSlippageBps5 >= cfg.restartMaxSlippageBps
  ) {
    return "RESTART";
  }

  // Healthy growth
  if (
    ctx.drawdownPct <= cfg.accelerateMaxDrawdownPct &&
    ctx.recentPnL5 > cfg.accelerateMinRecentPnL &&
    ctx.executionQualityScore >= cfg.accelerateMinExecQuality &&
    ctx.signalQualityScore5 >= cfg.accelerateMinSignalQuality
  ) {
    return "ACCELERATE";
  }

  // Everything else is recovery
  return "RECUPERATE";
}

6. Integration with Dynamic Position Sizing

Mode must directly modify risk budget.

Updated sizing pipeline

const baseRiskBudget = equity * riskConfig.riskPerTradePct;
const modeAdjustedRiskBudget = baseRiskBudget * modeProfile.riskMultiplier;

Rules

Accelerate
	•	allow 15–25% larger risk budget
	•	allow slightly larger notional when signal quality and liquidity are strong
	•	still block entries if execution quality is poor

Recuperate
	•	cut risk budget by 30–45%
	•	no size increase from recent wins
	•	stronger volatility throttling
	•	require better reward-to-risk

Restart
	•	no new entries
	•	optionally flatten open positions
	•	transition agent lifecycle to restart workflow

7. Integration with Dynamic Leverage

Mode adjusts leverage selection after the normal leverage model.

Updated leverage pipeline

const selectedLeverage = selectLeverage(signalCtx, leverageConfig);
const adjustedLeverage = applyModeLeverageBias(selectedLeverage, modeProfile, leverageConfig);

Example

function applyModeLeverageBias(
  selected: number,
  mode: CapitalModeProfile,
  cfg: LeverageConfig
) {
  const span = cfg.maxLeverage - cfg.minLeverage;
  const adjusted = selected + Math.round(span * mode.leverageBias);
  return clamp(adjusted, cfg.minLeverage, cfg.maxLeverage);
}

Rules

Accelerate
	•	can live in upper half of leverage range more often
	•	only if trend regime + signal quality + liquidity agree

Recuperate
	•	push leverage into lower half
	•	especially reduce leverage in chop or high ATR regimes

Restart
	•	leverage selection disabled because new entries disabled

8. Integration with Signal Engine

Mode must influence signal acceptance, not just score thresholds.

Updated decision pipeline

if (!modeProfile.allowNewEntries) return skip("mode_restart");

if (signal.finalScore < modeProfile.minSignalScore) {
  return skip("below_mode_threshold");
}

Mode behavior

Accelerate
	•	permits earlier participation in strong trend / breakout regimes
	•	accepts slightly lower threshold if execution quality is high
	•	favors continuation setups

Recuperate
	•	disallows mediocre setups
	•	avoids chop almost entirely
	•	favors mean-reversion only when structure is clear and volatility is controlled
	•	requires higher HTF agreement

Restart
	•	skips all new entries

10. Restart Workflow

Restart is not just a label. It must trigger a real workflow.

Restart states

type RestartStatus =
  | "NONE"
  | "PENDING_FLATTEN"
  | "PENDING_WITHDRAW"
  | "PENDING_ARCHIVE"
  | "READY_FOR_REDEPLOY"
  | "COMPLETED";

Workflow

Step 1

Disable all new entries immediately.

Step 2

If position open:
	•	request close
	•	verify close on-chain
	•	retry with bounded logic
	•	escalate to manual review if unresolved

Step 3

If funds remain:
	•	mark recoverable balance
	•	optionally transfer remaining free balance to savings/funding wallet
	•	store redeploy recommendation

Step 4

Archive agent:
	•	mark agent as retired_restart
	•	preserve logs and telemetry
	•	keep read-only in UI

Step 5

Offer redeploy:
	•	prefill Deploy Agent with last known good config
	•	optionally reduce starting aggression for new deploy

13. Hysteresis and Anti-Flapping

Do not let the mode switch rapidly every few minutes.

Rules
	•	minimum 30 minutes in a mode before switching unless hard restart condition triggered
	•	require threshold + buffer to move back into Accelerate
	•	Restart can trigger immediately
	•	Recovering from Restart must require new deployment, not mode flip

Example

function canSwitchMode(
  prevMode: CapitalMode,
  nextMode: CapitalMode,
  minutesInMode: number,
  hardFailure: boolean,
  cfg: CapitalModeConfig
) {
  if (hardFailure && nextMode === "RESTART") return true;
  if (minutesInMode < cfg.minModeDurationMin) return false;
  return true;
}
