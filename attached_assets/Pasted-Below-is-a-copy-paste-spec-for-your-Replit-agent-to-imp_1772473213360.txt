3) Implement Transaction Finality + Event Parsing (the big fix)

Add a TxMonitor service

When you submit ANY tx:
	1.	store digest immediately
	2.	waitForTransactionBlock
	3.	mark success/fail
	4.	parse events/objectChanges
	5.	update your DB models

async function confirmTx(digest: string) {
  const res = await suiClient.waitForTransactionBlock({
    digest,
    options: {
      showEffects: true,
      showEvents: true,
      showBalanceChanges: true,
      showObjectChanges: true,
      showInput: true,
    },
  });

  const status = res.effects?.status?.status; // "success" | "failure"
  return { status, res };
}

Parse “balance changes” into a ledger (mandatory)

type LedgerEntry = {
  agentId: string;
  wallet: string;
  digest: string;
  ts: number;
  coinType: string; // "0x2::sui::SUI"
  amount: bigint;   // signed
  kind: "GAS" | "ORDER_CREATE" | "CLOSE_FILL" | "REWARD_ESCROW" | "UNKNOWN";
  note?: string;
};

Create ledger entries from balanceChanges for the agent wallet + reward wallet.

This is how you stop “missing SUI” confusion.
You will literally see:
	•	order create debits
	•	close fill credits
	•	gas debits
	•	reward escrow transfers

…and anything not categorized becomes traceable.

Parse Typus events into canonical order/position records

You need to detect:
	•	order created (typus order id)
	•	position opened (positionId)
	•	position closed (close fill)
	•	keeper/escrow settlements (if applicable)

Even if you don’t know exact event types: do this pattern:

function extractTypusSignals(events: any[]) {
  return events
    .filter(e => String(e.type).toLowerCase().includes("typus"))
    .map(e => ({
      type: e.type,
      parsedJson: e.parsedJson,
    }));
}

Then map:
	•	clientOrderId ↔ typusOrderId ↔ positionId
If Typus doesn’t emit your clientOrderId, you must embed it in tx (memo) or maintain a digest↔intent mapping.

Minimum viable mapping:
	•	clientOrderId stored locally with the tx digest
	•	once tx confirmed, store typus order id from events
	•	later, poll typus “getOrder / getPosition” by order id until positionId exists
