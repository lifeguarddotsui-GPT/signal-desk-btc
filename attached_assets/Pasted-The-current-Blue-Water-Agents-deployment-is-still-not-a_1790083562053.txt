4. Allocation engine

Use score- and liquidity-weighted allocation.

Paper campaign defaults:

* starting balance: 10 virtual SUI;
* retain at least 30% in SUI;
* maximum total exposure: 70%;
* maximum allocation to one token: 30% of campaign equity;
* maximum three simultaneous positions.

Calculate preliminary weight:

weight = (score - 60) × liquidityAdjustment × exitabilityAdjustment

Normalize the weights across eligible Top Three candidates.

The result may resemble 40%/35%/25% of deployable capital, but must be calculated rather than hard-coded.

For the initial Mainnet canary:

* maximum funded campaign: 1 SUI;
* retain at least 0.7 SUI;
* maximum total deployed: 0.3 SUI;
* maximum first entry per token: 0.1 SUI;
* maximum three entries;
* do not use funds unless the owner explicitly arms the agent.

Any unused allocation remains SUI.

Never average down, borrow, leverage, or buy an ineligible asset.

5. Real Live Paper execution

Paper mode must operate continuously and automatically after the authenticated user presses Start Paper Campaign.

For each intended order:

1. Record the candidate and score snapshot.
2. Freeze the decision timestamp and checkpoint.
3. Generate a fresh executable quote.
4. Build the exact programmable transaction block Mainnet would use.
5. Run Sui transaction simulation.
6. Record simulation effects, balance changes, gas, errors, transaction-byte hash and quote.
7. If simulation fails, reject the order.
8. If it succeeds, create a virtual fill using the simulated output after modeled fees, slippage, price impact and gas.
9. Store the virtual token balance and cost basis.
10. Begin live exit monitoring.

Paper positions must be valued using current executable sell quotes, not last price, market cap, or fabricated returns.

If an exact transaction cannot be simulated, mark it UNEXECUTABLE. Never create a paper fill anyway.

For each approved entry:

1. Lock an idempotent order record.
2. Refresh the candidate.
3. Refresh curve state and reserves.
4. Obtain a quote no older than five seconds.
5. Set a positive minTokensOut.
6. Build the buy transaction.
7. Simulate it.
8. Compare expected output with simulation.
9. Sign through the isolated agent signer.
10. Submit to Sui Mainnet.
11. Wait for finality.
12. Parse actual balance changes and events.
13. Save the real digest.
14. Reconcile expected and actual balances.
15. Create the position only after finality.

The UI must show the real digest and explorer link. Never generate a fake digest.

Retries must use the same idempotency key and must never duplicate the economic order.

8. Exit-to-SUI engine

Evaluate every open position at least every 10 seconds using a fresh executable sell quote.

Use net liquidation value after fees, gas, slippage and price impact.

Initial strategy defaults for testing:

* hard stop: exit at −8% net liquidation return;
* first profit: sell 25% at +15%;
* second profit: sell 25% at +30%;
* trailing remainder: 10% trailing stop from highest executable liquidation value;
* score exit: exit when score remains below 60 for two evaluations;
* rank exit: exit when the token remains outside the Top Ten for two evaluations;
* flow reversal: exit when five-minute buy/sell ratio falls below 0.70 and unique sellers are increasing;
* creator exit: immediately exit on verified creator selling or dangerous clustered-wallet distribution;
* liquidity exit: exit when available exit liquidity falls by 25% or projected price impact exceeds policy;
* time exit: close after 90 minutes unless the position remains profitable, Top Three-ranked, and momentum-positive;
* graduation exit: exit before migration if the post-graduation DEX route is not verified.

Before entering any position, prove that its expected token output can be passed into the verified sell builder. No buy-only integrations are permitted.

For a sell:

1. Refresh the real token balance.
2. Request an executable sell quote.
3. Set positive minSuiOut.
4. Simulate the sell.
5. Sign and submit.
6. Wait for finality.
7. Parse actual SUI received.
8. Reconcile the ledger.
9. Update realized P&L.
10. Link the transaction digest.

If a normal sell fails, stop new entries and retry only within the configured bounded policy. Do not repeatedly submit blind transactions.
