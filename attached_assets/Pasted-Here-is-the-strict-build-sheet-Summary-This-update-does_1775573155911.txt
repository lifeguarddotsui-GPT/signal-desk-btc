Here is the strict build sheet.

Summary

This update does three things for Blue Water’s SUI/USDC perps-only system:
	1.	Improves trade selection
by forcing every signal through a regime-aware probability engine before any order is allowed.
	2.	Improves live learning
by making the system adapt only from real closed trades, so it learns which setup types are actually winning right now.
	3.	Improves execution discipline
by converting signal quality into a strict policy: skip, probe, standard, or press size, with cost-aware approval and regime-specific exits.

Net effect

After this build, the agent should:
	•	take fewer bad trades
	•	stop repeating the same losing setup
	•	size down weak entries
	•	size up only when conditions are truly aligned
	•	produce cleaner, more explainable decisions in the UI and database

2.2 Regime logic rules

Implement these exact rules.

Trend up

Use when all are true:
	•	emaFast > emaSlow
	•	emaFast - emaSlow expanding
	•	rsi >= 55
	•	priceNow >= vwap
	•	volatilityPct5m not collapsed

Trend down

Use when all are true:
	•	emaFast < emaSlow
	•	spread expanding downward
	•	rsi <= 45
	•	priceNow <= vwap

Chop low vol

Use when:
	•	EMA spread is narrow
	•	price near VWAP
	•	RSI between 45 and 55
	•	1m and 5m vol both low
	•	breakout expansion weak

Chop high vol

Use when:
	•	directional structure weak
	•	volatility elevated
	•	repeated VWAP crossing likely
	•	breakout expansion noisy

Breakout expansion

Use when:
	•	range expansion strong
	•	EMA spread widening
	•	RSI slope strong
	•	price separating from VWAP
	•	BTC agreement positive

Mean reversion

Use when:
	•	distance from VWAP stretched
	•	RSI extreme
	•	expansion cooling
	•	EMA spread no longer accelerating

4.3 Required scoring flow

Step 1. Base score

Use normalized weighted inputs:
	•	regime confidence
	•	trend strength
	•	breakout score
	•	BTC agreement
	•	open interest delta
	•	book imbalance
	•	RSI slope
	•	distance from VWAP

Step 2. Live modifier

Fetch:
	•	recent same-cluster stats
	•	recent same-regime stats
	•	recent same-side stats

Then:
	•	add positive adjustment when those stats are strong
	•	subtract negative adjustment when weak

Step 3. Convert to probability

Clamp final probability between 0.01 and 0.99.

Step 4. Expected edge

Use:

expectedEdgeBps = (probability * grossTakeProfitBps) - ((1 - probability) * grossStopLossBps) - estimatedTotalCostBps;

Use regime-specific default TP/SL assumptions if no execution plan exists yet.

Step 5. Hard rejection

Reject if:
	•	probability below regime minimum
	•	confidence below regime minimum
	•	expected edge below threshold
	•	breakout long/short against BTC agreement
	•	chop regime with weak expansion
