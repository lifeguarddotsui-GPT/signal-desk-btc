# Blue Water Agents - AI Trading Platform

## Overview
Blue Water Agents is a Web3 AI trading platform designed for autonomous trading of SUI-USDC perpetual contracts using a dual-agent architecture. It provides a Market Dashboard with live Pyth Oracle data, professional charting, and AI Signal Reasoning. The platform enables users to deploy, manage, and monitor trading agents, claim rewards, and access protocol statistics. A core principle is transparency through verifiable on-chain transactions, ensuring all agent actions are user-initiated and auditable. The project aims to establish a robust, transparent, and user-centric platform for AI-driven perpetual futures trading within the Web3 ecosystem.

## System Architecture
The platform utilizes a React, Vite, Tailwind CSS, and shadcn/ui frontend, integrated with SUI wallets via `@mysten/dapp-kit`. The backend is built with Express.js, PostgreSQL (managed by Drizzle ORM), and incorporates a WebSocket server for real-time data communication.

**Core Architectural Decisions & Features:**

-   **Dual-Agent System:** Each deployment consists of an Execution Agent (managing wallet, balances, orders, positions, and risk) and an automatically generated Signal Sub-Agent (performing indicator analysis and generating trading signals based on a 4-of-7 condition score with margin requirements).
-   **DEX Execution Engine:** Uses a `DexAdapter` interface for Typus Perps, executing direct on-chain Move calls. Trades require successful on-chain execution, with no simulation fallback. Supports up to 5 concurrent positions per agent with locked collateral tracking and a 30-second cooldown for same-direction trades. **Keeper-Based Market Orders:** `create_trading_order` is submitted on-chain, then the Typus keeper network fills the order (typically within seconds). `match_trading_order` is now keeper-only (Typus contract upgrade Feb 2026 — `unauthorized` error for non-keeper wallets). After order creation, the system polls for keeper fill (15s for opens, 15s for closes). If not filled, the unfilled order is cancelled to recover collateral. Gas budget: 30M MIST per order. **Per-Position Close Gas Cap:** Maximum 0.5 SUI total gas and 5 close attempts per position. If exceeded, position is force-settled from on-chain state to prevent gas drain. **Market Order Enforcement:** Pre-order validation blocks any order where trigger/oracle ratio would create a stop order (LONG open needs ratio >1.02, SHORT open needs ratio <0.98; close orders use inverse thresholds). Current slippage: LONG=500bps(5%), SHORT=1000bps(10%) — producing ratios 1.05 and 0.90 respectively, well within market order zone. Post-cancel balance verification syncs agent balance from on-chain after any cancelled unfilled order. **Balance-Confirmed Fill Detection:** When cancel returns `order_not_found`, the system snapshots pre/post on-chain balance. If the balance dropped by ~collateral amount, the order is treated as keeper-filled (position created in DB). A background `PositionResolver` retries on-chain ID resolution every 15s (up to 20 attempts). Event scan pages increased to 15 (750 events) with 10s indexer wait. `processPendingUnfilledOrders` also uses balance-gap heuristics before declaring collateral lost. Startup integrity check `detectUntrackedPositions` searches for unexplained balance gaps and recovers filled orders.
-   **Position Management & PnL Integrity:** Robust handling of Typus's two-step `position_id` assignment process (from `CreateTradingOrderEvent` to `OrderFilledEvent`). Includes mechanisms for close fill verification (scanning both ToAddress and FromAddress TX history, matching `linked_position_id`), ensuring collateral return before confirming closure. No "external close" concept — positions are either on-chain verified, settled on-chain (position gone from DEX with balance reconciliation), or liquidated. Per-position PnL is maintained, and agent-level `totalPnl` is reconciled from on-chain balance. Phantom close prevention and startup integrity checks ensure data consistency. **Collateral Protection:** Post-close balance verification confirms wallet balance actually reflects returned collateral. Balance is NEVER inflated above on-chain truth — when settlement is unconfirmed or RPC fails, conservative estimates are used. Settlement wait is 30s. **Price Guard Protection:** For `settled_onchain` positions (where price analysis confirms the position was NOT liquidated), the system NEVER overrides price-based PnL with wallet balance analysis. This prevents gas costs from failed close attempts being misclassified as trade losses. **On-Chain Liquidation Detection:** Startup integrity scans wallet TX history for real `LiquidateEvent` events and replaces synthetic close digests with actual on-chain TX hashes. **PnL Recalculation:** A `/api/agents/:id/recalculate-pnl` endpoint detects and corrects misclassified positions (e.g., profitable trades incorrectly stored as full losses due to gas cost confusion). The startup integrity check also auto-corrects these on every boot.
-   **Transaction Safety & Recovery:** Features a per-wallet transaction queue, `CoinManager` for gas reserves, `safe-execute` with retry logic, and dry-run preflights. Transactions are limited by an allowlist for approved Move call targets and oracle modules. Endpoints for analyzing and importing lost deposit records are available. **Orphaned Order Recovery:** On startup, the integrity check scans all agent wallets for unfilled orders on Typus that were never cancelled or filled using paginated TX scanning (up to 250 TXs per direction across 5 pages). It automatically cancels them to recover locked collateral. A "Verify & Recover" button in the UI calls both `/api/agents/:id/recover-orphaned-orders` and `/api/agents/:id/recalculate-pnl` to recover orphaned orders AND fix misclassified position PnL. The `scanAndRecoverOrphanedOrders` method in `TypusAdapter` uses `findAllUnfilledOrderIds()` which comprehensively cross-references `CreateTradingOrderEvent`, `OrderFilledEvent`, and `CancelTradingOrderEvent` across the full paginated TX history. **Pre-Close Cleanup:** Before creating any new close order, `closePosition()` automatically cancels ALL existing unfilled close orders linked to the target position, preventing `too_many_linked_orders` accumulation. Close cooldown is 60s to prevent gas waste on retry loops.
-   **Anti-Liquidation Protection:** A three-tier system (stop-loss auto-tightening, hard max collateral loss cap, emergency close) protects against liquidation, designed to mitigate risks as Typus does not support native on-chain SL/TP orders. **Per-Position Close Gas Cap:** Maximum 0.15 SUI total gas and 3 close attempts per position. If exceeded, on-chain position existence is verified before force-settling — if position still exists on Typus, agent is PAUSED instead of force-settled. If RPC fails during check, agent is also paused for safety. **CRITICAL GUARD:** Force-settle is BLOCKED for positions without a valid on-chain position_id — only real on-chain TX submissions count toward the gas/attempt cap, not adapter rejections. Gas tracking (`trackCloseGasSpend`) is called AFTER the adapter close attempt, never before. Positions without on-chain IDs trigger inline resolution (event scan + side/size match) before returning an error. **Pre-Close Existence Check:** Before spending gas on any close TX, the system verifies the position actually exists on Typus via `getPositions()` event scan — if position is already gone, it settles without spending gas. **Unresolved Position Guard:** New trades are BLOCKED if any existing position has an unresolved on-chain ID (UUID-style), preventing additional collateral exposure while positions can't be managed. **Strict RPC Balance Policy:** The adapter NEVER falls back to DB balance if RPC is unavailable — it blocks the trade entirely to prevent sizing errors. **Daily Gas Caps:** Agent auto-pauses after 0.03 SUI or 5 failed transactions in 24 hours.
-   **Monitoring and Control:** A `Position Monitor` continuously checks open positions against Pyth prices for stop-loss, take-profit, and emergency triggers. A `Circuit Breaker` pauses agents after consecutive failed `OPEN` operations, and a `Daily Spend Cap` pauses agents if gas costs exceed thresholds.
-   **Oracle Integration:** Primary price data is sourced from Pyth Network's Hermes API (SUI/USD), with price validation and stale price guards.
-   **Gas Management:** Employs a two-tier gas policy and dynamic budgeting with a safety margin to prevent transaction failures due to insufficient gas. Supports coin merging.
-   **Agent Ownership & Rewards:** Agents are tied to the creator's wallet, requiring owner authentication for deletion. Rewards are configurable via `rewardSharePct`, and their persistence is ensured even upon agent deletion. Rewards are escrowed on-chain immediately when a profitable position is closed — the escrow happens AFTER settlement confirmation and BEFORE the DB balance update, so the reward is deducted from the agent wallet's on-chain balance and the DB balance accurately reflects the post-escrow state. If the wallet lacks sufficient balance for the full reward, a reduced reward (up to available balance) is escrowed. No IOUs or `pending_escrow` records are created — only real on-chain transfers generate reward records. **Force-Settle Recovery:** Startup integrity and Verify & Recover detect positions with `closeTxDigest=settled_onchain` that were never actually closed on-chain. These are reopened, their associated rewards voided, and queued for proper on-chain close. The `getPositions()` method in TypusAdapter uses **direct event queries** (`queryEvents` with `MoveEventType` filter) to find `OrderFilledEvent` and `LiquidateEvent` for the wallet address — NOT wallet TX history scanning, because Typus keeper fills happen in the keeper's TXs (not the agent's). This was a critical fix: the old TX-scanning approach found 0 positions because `OrderFilledEvent` lives in keeper TXs.
-   **Comprehensive Portfolio Display:** The "My Agents" page shows a full on-chain-verified breakdown: Total Portfolio Value (wallet + positions + pending orders + unrealized PnL), On-Chain Wallet balance, In Positions (locked collateral), In Pending Orders (collateral awaiting match), Unrealized PnL, and an Accounting section (net deposited, realized PnL, gas costs, unrecovered collateral). Pending unfilled orders are tracked separately from lost collateral. **Unrecovered SUI Detail:** When unrecovered SUI is detected (>0.01), the activity endpoint checks on-chain for force-settled positions still open on Typus and returns `unrecoveredDetails[]` with type (`on_typus`, `force_settled`, `unknown`), amount, location, on-chain ID, and whether it's recoverable. The frontend displays this detail with AlertTriangle icons and recovery instructions.
-   **SUI Flow Tracker:** A `/sui-flow` page with backend `GET /api/agents/:id/sui-flow` endpoint that scans on-chain wallet transaction history (`queryTransactionBlocks` with `FromAddress`/`ToAddress`, 5 pages × 50, `showEffects: true` for gas data). Categorizes every SUI movement: `deposit_in`, `order_create`, `order_cancel`, `close_fill`, `reward_escrow`, `failed_close`, `gas_spent`, `unknown_outflow`. Failed close attempts (TXs that call `create_trading_order` but fail) are labeled `failed_close` with orange badges. Cross-references with DB orders/positions/rewards/deposits. Returns summary (totalIn, totalOut, totalGas, totalLocked, totalReturned, totalRewards, unexplainedGap) and error highlights (failed TXs, unknown outflows, unfilled orders, failed closes). Frontend: agent selector → 6 summary cards → visual flow diagram (User Wallet → Agent Wallet → Typus DEX → Agent Wallet → Reward Wallet) → filterable transaction timeline with type badges, explorer links, and error highlighting.
-   **UI/UX Design:** Features a dark crypto trading theme with a teal primary color, CSS variable-based charting, and mobile-first responsive design. The "My Agents" page provides a unified fund status, per-position collateral risk bars, and streamlined wallet summaries.
