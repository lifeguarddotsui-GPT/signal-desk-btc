E. Make wallet flow the source of truth for position accounting

This is the most important change.

New rule

Positions should be tracked as lifecycle objects derived from wallet history + execution records, not only from live on-chain scan.

Current bad model

“Try to recover open positions from chain state.”

That fails when:
	•	RPC is slow
	•	protocol API misses a position temporarily
	•	close is in-flight
	•	settlement is pending
	•	front end refresh happens mid-lifecycle

New model

Maintain a local persistent state machine.

Create a Position Ledger table

type PositionLedger = {
  id: string;
  agentId: string;
  logicalPositionId: string;
  openDigest?: string;
  closeDigest?: string;
  protocolPositionId?: string;
  symbol: string;
  side: 'long' | 'short' | 'unknown';
  collateralSent: number;
  leverage?: number;
  notionalEstimate?: number;
  status:
    | 'opening'
    | 'open'
    | 'closing'
    | 'settling'
    | 'closed'
    | 'failed'
    | 'orphaned';
  fundingWalletAddress: string;
  protocolAddress?: string;
  openedAt?: number;
  closedAt?: number;
  settledAt?: number;
  returnedAmount?: number;
  pnlRealized?: number;
  linkedDigests: string[];
  metadata?: any;
};

State transitions

When funding wallet sends collateral to protocol

Create or update a position:

opening -> open

Even before external protocol confirmation, persist it as:
	•	opening
	•	then open once confirmed

When close order is submitted

Mark:

open -> closing

When protocol no longer shows live exposure but capital not yet returned

Mark:

closing -> settling

When capital returns to funding wallet

Match inflow and mark:

settling -> closed

This guarantees no vanishing positions.
