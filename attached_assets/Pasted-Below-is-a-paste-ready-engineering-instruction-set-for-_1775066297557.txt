BlueWaterAI Engineering Instructions

Goal

Upgrade the BlueWaterAI codebase so agents become:
	1.	Profitable
	•	Primary KPI: funding_wallet_value > net_deposit
	2.	Continuously active
	•	Agents should avoid long idle periods unless blocked by risk logic
	3.	Higher win rate
	•	Fewer low-quality entries
	4.	Clearer UI
	•	Users must understand why trades fired or did not fire
	5.	Smoother execution
	•	Faster decisions, fewer failed or late entries, cleaner state handling

⸻

Top 3 Priority Features to Build

1. Trade Probability Engine

Build a fully implemented trade probability scoring system and make it the center of all entry logic.

2. Risk-Adjusted Position Sizing Engine

Do not allow fixed trade size only. Position size and leverage must adjust based on confidence, volatility, drawdown, and execution quality.

3. Agent Memory + Post-Trade Learning Loop

Every trade must produce a feedback record so the system learns what setups actually make money.

Required Codebase Changes

A. Create a trade_probability module

Purpose

Every candidate trade must receive a probability score from 0-100.

This score must be computed before order submission.

New files
	•	src/engine/trade_probability.ts
	•	src/engine/probability_features.ts
	•	src/engine/probability_weights.ts
	•	src/types/tradeProbability.ts

Required output shape

export interface TradeProbabilityResult {
  probabilityScore: number; // 0-100
  confidenceBand: "very_low" | "low" | "medium" | "high" | "very_high";
  direction: "long" | "short";
  featureBreakdown: {
    trendAlignment: number;
    momentumQuality: number;
    volumeQuality: number;
    volatilityQuality: number;
    liquidityQuality: number;
    executionQuality: number;
    higherTimeframeAlignment: number;
    marketRegimeFit: number;
    recentAgentPerformance: number;
    newsSentimentBias?: number;
  };
  penalties: {
    spreadPenalty: number;
    chopPenalty: number;
    drawdownPenalty: number;
    slippagePenalty: number;
    lowLiquidityPenalty: number;
  };
  reasons: string[];
}

Scoring framework

Start with baseScore = 50.

Then adjust score with weighted factors.

Positive factors
	•	EMA trend alignment
	•	RSI direction quality
	•	MACD confirmation
	•	volume expansion
	•	orderbook / liquidity quality
	•	higher timeframe agreement
	•	low spread
	•	strong recent setup performance
	•	favorable market regime

Negative factors
	•	chop / sideways market
	•	weak volume
	•	wide spread
	•	high recent slippage
	•	poor recent performance on same setup
	•	high volatility without trend confirmation
	•	adverse news sentiment if integrated

Example scoring logic

score = 50
+ trendAlignment
+ momentumQuality
+ volumeQuality
+ liquidityQuality
+ higherTimeframeAlignment
+ marketRegimeFit
+ recentAgentPerformance
- chopPenalty
- spreadPenalty
- slippagePenalty
- drawdownPenalty
- lowLiquidityPenalty

Clamp final score:

score = Math.max(0, Math.min(100, score));

Confidence bands
	•	0-39 = very_low
	•	40-54 = low
	•	55-69 = medium
	•	70-84 = high
	•	85-100 = very_high

B. Make probability score mandatory in entry logic

Requirement

No trade may open unless TradeProbabilityResult exists.

New entry rules

Replace current loose signal firing with:

if (probabilityScore < strategy.minProbabilityThreshold) {
  rejectTrade("Probability below threshold");
}

Default thresholds by mode
	•	Now: 58
	•	Auto: 62
	•	Aggressive: 55
	•	Precision: 70

These must be configurable per agent.

Add to agent config

minProbabilityThreshold: number;

C. Build dynamic position sizing

New files
	•	src/engine/position_sizing.ts
	•	src/types/positionSizing.ts

Required inputs
	•	probability score
	•	current account equity
	•	net deposit
	•	funding wallet balance
	•	recent realized pnl
	•	drawdown %
	•	current volatility
	•	spread/slippage estimate
	•	open exposure
	•	market regime

Required output

export interface PositionSizingResult {
  collateralSize: number;
  leverage: number;
  maxLossUsd: number;
  expectedRiskReward: number;
  sizingReason: string[];
}

Sizing rules

Use probability score tiers.

Tier 1: weak setup
	•	score < 60
	•	no trade or minimum scout size only

Tier 2: decent setup
	•	score 60-69
	•	small size
	•	normal leverage

Tier 3: strong setup
	•	score 70-84
	•	medium size
	•	slightly increased leverage only if volatility is contained

Tier 4: elite setup
	•	score 85+
	•	largest allowed size within risk limits

Hard risk limits
	•	Max risk per trade: configurable, default 0.5% to 1.25% of equity
	•	Max total open exposure: configurable
	•	Reduce size automatically if:
	•	drawdown > threshold
	•	slippage elevated
	•	win rate falling
	•	realized pnl negative over recent rolling window

Leverage rules

Leverage must be dynamic, not fixed only.

Example:

if (volatilityHigh || spreadWide) leverage = lower;
if (probabilityHigh && volatilityContained) leverage = higher;

Never allow leverage increase purely from confidence if execution conditions are poor.

Inputs

Why this matters

Probability score and strategy behavior must depend on regime.

Strategy behavior
	•	trend_up: prefer longs
	•	trend_down: prefer shorts
	•	range: fade edges or reduce trend entries
	•	chop: heavily penalize entries
	•	volatility_breakout: allow breakout logic
	•	low_activity: either idle or micro-scalp only

F. Add profitability-first trade filtering

Requirement

The agent should not aim for “more trades” blindly.
It should aim for positive expectancy.

Build expectancy calculation

New file:
	•	src/engine/expectancy.ts

expectancy = (winRate * avgWin) - ((1 - winRate) * avgLoss)

Use rolling windows
	•	last 20 trades
	•	last 50 trades
	•	last 100 trades
	•	by asset
	•	by direction
	•	by setup signature

Rule

If recent expectancy is negative for a setup, reduce:
	•	trade frequency
	•	position size
	•	leverage

If expectancy is deeply negative, block setup temporarily.

G. Add continuous trading without forcing bad trades

Problem

Agents should not sit idle forever, but also should not be forced into garbage entries.

Solution

Introduce three activity layers:

Layer 1: Premium setups
	•	full position sizing
	•	full threshold

Layer 2: Standard setups
	•	moderate size
	•	moderate threshold

Layer 3: Anti-idle micro setups
	•	only if market is liquid and spread is tight
	•	tiny position size
	•	fast TP/SL
	•	strict time stop

Add anti-idle logic

New file:
	•	src/engine/anti_idle.ts

Rules

If no trade in X minutes:
	1.	check regime
	2.	check spread/liquidity
	3.	allow micro-scalp mode only in acceptable conditions
	4.	forbid anti-idle trades in chop + wide spread

I. Create risk state modes for the agent

New files
	•	src/engine/risk_mode.ts

Required modes
	•	Normal
	•	Accelerate
	•	Recuperate
	•	Restart

Logic

Normal
Default

Accelerate
Conditions:
	•	rolling profitability positive
	•	drawdown low
	•	execution quality good
	•	win rate stable

Effect:
	•	slightly higher size
	•	slightly lower cooldown
	•	keep hard risk caps

Recuperate
Conditions:
	•	recent losses but not catastrophic

Effect:
	•	smaller trades
	•	higher threshold
	•	focus on best setups only

Restart
Conditions:
	•	large drawdown
	•	persistent negative expectancy
	•	repeated execution failures

Effect:
	•	stop live trading
	•	only paper / observation mode
	•	user prompt to refund / reconfigure / rebuild

Recommended Default Formula Set

Probability score formula

score =
50
+ trendAlignmentScore
+ momentumScore
+ volumeScore
+ liquidityScore
+ higherTfAlignmentScore
+ regimeFitScore
+ recentSetupPerformanceScore
- chopPenalty
- spreadPenalty
- slippagePenalty
- drawdownPenalty
- lowLiquidityPenalty;

Trade decision

if (score < threshold) reject;
else approveCandidate;

Position sizing logic

riskBudgetUsd = equity * riskPct;

if (score >= 85) sizeMultiplier = 1.25;
else if (score >= 70) sizeMultiplier = 1.0;
else if (score >= 60) sizeMultiplier = 0.6;
else sizeMultiplier = 0.0;

Then reduce with penalty multipliers:

if (highVolatility) sizeMultiplier *= 0.7;
if (highSlippage) sizeMultiplier *= 0.6;
if (drawdownMode) sizeMultiplier *= 0.5;
