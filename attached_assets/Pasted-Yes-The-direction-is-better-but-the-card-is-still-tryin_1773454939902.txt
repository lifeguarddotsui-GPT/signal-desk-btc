In Transit backend plan

Yes, if In Transit is always null/blank, then there is probably no full backend infrastructure yet.

You need a dedicated system for it.

Minimum infrastructure required

Table: pending_value_movements

type PendingValueMovement = {
  id: string
  userId: string
  agentId?: string
  type:
    | 'POSITION_CLOSE_SETTLEMENT'
    | 'WALLET_TRANSFER'
    | 'REWARD_CLAIM'
    | 'WITHDRAWAL'
    | 'INTERNAL_REBALANCE'
  amount: number
  asset: 'SUI'
  status:
    | 'INITIATED'
    | 'SUBMITTED'
    | 'SOURCE_CONFIRMED'
    | 'DESTINATION_PENDING'
    | 'SETTLED'
    | 'FAILED'
  sourceWallet?: string
  destinationWallet?: string
  txHash?: string
  createdAt: string
  updatedAt: string
}

Computation

inTransitValue =
  sum(all pending_value_movements where status != 'SETTLED' && status != 'FAILED')

Without something like this, In Transit is just theater.

Final design principle

The portfolio card should answer three questions, in this order:
	1.	How much do I economically have?
	2.	Where is it right now?
	3.	How certain is that number?

Everything else should be secondary.

Right now the app is closer than before, but the next leap is:
	•	include savings wallets in wallet total
	•	make in-transit real
	•	move reconciliation info into a separate health section
